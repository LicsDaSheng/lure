# Pi 桌面终端 UI 设计规约

本规约定义 Lure 当前界面与交互的最终状态。

## 产品与界面边界

- Lure 是面向单个用户的 Pi 桌面终端，不包含账户、组织、团队、订阅或协作能力。
- 主工作区直接呈现 Pi 原生 TUI；模型、认证、会话、命令、工具、skills 和 extensions 均由 Pi 提供。
- Lure 只负责窗口、工作目录、PTY 生命周期、终端输入输出、尺寸同步和故障恢复。
- 不解析 ANSI/VT 内容，不重建 Agent、工具、会话或 TUI 组件语义。
- 不在终端外重复实现 Pi 功能，不设置常驻侧栏、右栏、文件树或独立对话流。

## 页面布局

```text
┌──────────── 自定义标题栏（48px）────────────┐
│ 窗口控制 · Lure / 工作目录 · 终端操作       │
├─────────────────────────────────────────────┤
│                                             │
│              Pi TUI / xterm.js              │
│                                             │
└─────────────────────────────────────────────┘
```

- 应用采用单一终端工作区。
- 自定义标题栏高 48px：左侧为窗口控制，中部显示工作目录，右侧提供选择目录、重新启动和停止操作。
- 工作目录过长时截断显示，并保留完整的可访问名称。
- 终端填满标题栏之外的空间，仅保留避免文字贴边的必要内边距。
- 最小窗口尺寸为 720 × 480；窗口变化后重新计算终端列数和行数并同步 PTY。
- 根容器禁止页面滚动和 overscroll，滚动仅发生在 xterm.js viewport。
- 状态面板覆盖终端区域，但不遮挡标题栏和窗口控制。

## 终端行为

- xterm.js 原样呈现 PTY 输出，不由 React 重新排版、Markdown 化或转换为消息卡片。
- xterm.js 负责 ANSI/VT、alternate screen、光标、选择、scrollback、链接和终端输入编码。
- 终端获得焦点后将输入直接写入 PTY，不解析命令。
- Pi TUI 拥有终端区域内的键盘、鼠标、粘贴、快捷键和 slash command 语义。
- Lure 不抢占终端快捷键；窗口级操作通过标题栏按钮完成。
- 启动成功后自动聚焦终端；目录选择结束后恢复终端焦点。
- 选择新目录时先停止当前 Pi，再在新目录启动；取消选择不影响当前会话。
- 停止或退出后保留已有终端内容，并允许在相同目录重新启动。
- 关闭窗口时回收 Pi 子进程、PTY reader、事件订阅和相关任务。

## 状态与恢复

- 启动中显示低干扰状态，不伪造 Pi 输出。
- 启动失败时展示具体错误、当前影响以及重试和选择目录操作。
- Pi 退出后展示退出状态和重新启动操作，不清空终端内容。
- 输出或输入转发失败时保留已显示内容，并提供可执行的恢复路径。
- 不自动无限重启 Pi。

## 视觉与可用性

- 窗口外框使用 16px 圆角、细边框和透明原生窗口背景。
- 应用统一使用浅色 Gruvbox 主题，应用外壳与 Pi TUI 保持一致的暖色视觉语言。
- 主背景和终端背景为 `#FBF1C7`，标题栏背景为 `#EBDBB2`，主要前景为 `#3C3836`，次要前景为 `#7C6F64`。
- 终端使用完整的 Gruvbox Light ANSI 色板；默认字号 13px，行高约 1.25，字号不得低于 12px。
- 终端字体优先使用 `SFMono-Regular`、`Menlo`、`Monaco`、`Consolas` 和通用 monospace。
- 状态面板使用 Gruvbox 浅色卡片和低对比边框，不使用大面积高饱和色。
- 所有按钮必须具有可访问名称、键盘焦点态和足够的点击区域。
- 状态和错误不能只依赖颜色表达，必须包含文字。
- 终端工作区必须具有用途标签，xterm.js 输入区域保持可聚焦。
- 系统启用“减少动态效果”时停止非必要动画。
