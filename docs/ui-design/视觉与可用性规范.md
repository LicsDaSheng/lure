# 视觉与可用性规范

## 视觉语言

- 风格应安静、可信、面向个人工作流；避免复杂开发者控制台感。
- 左侧导航使用暖中性浅灰 `#F6F6F8`，主区使用白色 `#FFFFFF`，以 `#E5E5E8` 的细线建立双栏层级；避免大面积高纯黑和强边框。
- 通过字号、字重、间距及轻微背景差建立层级；强调色只用于主要操作和状态。
- 蓝或紫表达进行中和可操作，绿表达成功，黄表达注意，红仅用于失败和危险操作。
- 桌面应用外框使用 16px 圆角与 `#E5E5E8` 细边框，并通过透明原生窗口露出真实圆角；常规控件圆角为 8px，内容卡片圆角为 12px；底部悬浮输入卡使用 20px 圆角、`#E5E5E8` 描边和 `0 6px 24px rgba(0,0,0,.05)` 轻阴影。
- 普通对话使用易读无衬线字体；代码、路径、命令和工具输出使用等宽字体。
- 示例操作使用高 32px、间距 8px 的浅灰轻量标签或按钮（`#F4F4F6`）；窄窗口自然换行。
- 输入卡底部控制栏保持单行；模型名称限宽并省略，空间不足时优先隐藏 12px 低对比快捷键提示。发送或停止按钮固定在最右侧，是输入卡内唯一高对比主操作。
- 导航会话行内布局宽度固定：标题列占行内剩余宽度、时间列固定宽度右对齐，不随时间文案伸缩；超长标题由悬停跑马灯承担完整展示，不使用原生悬浮提示。
- 对话正文使用 13px 字号、约 20px 行高；正文标题使用 15–18px 并收紧字距。用户消息、Agent 结果和输入框使用一致的正文尺度，执行状态与上下文信息使用 12px。
- 主文本使用 `#303136`，标题使用 `#2B2C30`，次级文本使用 `#74757B`，弱化状态使用 `#9A9BA1`；行内代码使用 `#526065` 文字和 `#F0F0F2` 背景，不以高饱和强调色抢占正文层级。
- 按钮状态使用明确色值而非整体透明度推导：主按钮依次使用默认 `#34353A`、悬停 `#292A2E`、按下 `#202125`、禁用 `#D6D6DA`；浅色按钮悬停使用 `#EAEAED`、按下使用 `#E1E1E5`，幽灵按钮悬停使用 `#ECECEF`、按下使用 `#E3E3E7`，禁用文字使用 `#ADADB3`。
- 对话内容的可读宽度为 720px；外层内容列通过 24px 内边距扩展到 768px，使正文与 720px 输入卡左边缘对齐。

## 文案原则

- 使用用户可理解的行为描述，避免仅出现底层工具名或命令。
- 状态、错误和确认文案要先描述结果或影响，再说明技术原因。
- 按钮使用明确动词，如“重试”“查看日志”“应用变更”；避免“确定”“继续”等含混表述。

## 可用性与无障碍

- 所有交互控件都要有可见标签或悬浮说明。
- 执行过程的折叠触发器必须是真实按钮，提供 `aria-expanded`、可访问名称和关联内容；箭头与文案共同表达展开状态，不能只靠颜色区分。
- 折叠触发器同时说明状态与点击后的行为，点击区域不低于 36px，以细分隔线、字重和间距建立层级，避免重边框与大块状态色。
- 不以颜色作为状态、错误或选中态的唯一表达；应同时使用文字、图标或形状。
- 正文和背景保持足够对比度，弱化文本也必须可读。
- 焦点态清晰可见；打开模态或抽屉后，键盘焦点应被限制在浮层内。
- 加载、状态变化和结果更新需要能被辅助技术读取。
- 点击目标最小可操作面积建议不低于 36 × 36px。
