# 视觉与可用性规范

## 视觉语言

- 风格应安静、可信、面向个人工作流；避免复杂开发者控制台感。
- 左侧导航使用暖中性浅灰 `#F6F6F8`，主区使用近白 `#FEFEFF`，以 `#E8E8EB` 的细线建立双栏层级；避免大面积高纯黑和强边框。
- 通过字号、字重、间距及轻微背景差建立层级；强调色只用于主要操作和状态。
- 蓝或紫表达进行中和可操作，绿表达成功，黄表达注意，红仅用于失败和危险操作。
- 常规控件圆角为 8px，内容卡片圆角为 12px；底部悬浮输入卡使用 20px 圆角、`#E8E8EB` 描边和 `0 6px 24px rgba(0,0,0,.05)` 轻阴影。
- 普通对话使用易读无衬线字体；代码、路径、命令和工具输出使用等宽字体。
- 示例操作使用高 32px、间距 8px 的浅灰轻量标签或按钮（`#F4F4F6`）；窄窗口自然换行。
- 输入卡底部控制栏保持单行；模型名称限宽并省略，空间不足时优先隐藏 12px 低对比快捷键提示。发送或停止按钮固定在最右侧，是输入卡内唯一高对比主操作。

## 文案原则

- 使用用户可理解的行为描述，避免仅出现底层工具名或命令。
- 状态、错误和确认文案要先描述结果或影响，再说明技术原因。
- 按钮使用明确动词，如“重试”“查看日志”“应用变更”；避免“确定”“继续”等含混表述。

## 可用性与无障碍

- 所有交互控件都要有可见标签或悬浮说明。
- 不以颜色作为状态、错误或选中态的唯一表达；应同时使用文字、图标或形状。
- 正文和背景保持足够对比度，弱化文本也必须可读。
- 焦点态清晰可见；打开模态或抽屉后，键盘焦点应被限制在浮层内。
- 加载、状态变化和结果更新需要能被辅助技术读取。
- 点击目标最小可操作面积建议不低于 36 × 36px。
