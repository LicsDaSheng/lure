# 用户交互规范

## 任务生命周期

| 操作 | 系统行为 |
|---|---|
| 新建任务 | 创建空白会话，进入主区并聚焦输入框。 |
| 发送指令 | 记录输入，创建执行流，滚动至最新状态。 |
| Agent 执行 | 依序更新计划、工具摘要、进度与阶段结果。 |
| 等待输入 | 明确需要补充的内容，并提供下一步提示。 |
| 完成任务 | 展示结果摘要和结果卡片，状态更新为已完成。 |
| 归档任务 | 移至已归档，保留全部记录与恢复能力。 |
| 删除任务 | 说明影响范围并要求最终确认；删除后回到最近任务或空状态。 |

## Agent 状态与反馈

统一使用：准备中、执行中、等待输入、已完成、已失败、已停止。

- 状态必须以文字表达，颜色和动画仅作辅助。
- 执行中显示当前步骤和耗时；超时或长时间等待时提供查看详情或停止操作。
- 用户停止的任务标记为“已停止”，不得表达为失败。
- 所有状态变化在执行流内保留可追溯记录。

## 渐进展开

- 默认呈现关键结果和摘要；长日志、原始参数和完整堆栈按需展开。
- 展开或收起某项工具调用不得影响其他内容。
- 完整内容使用抽屉或模态在当前任务内打开；关闭后恢复原滚动位置和展开状态。
- 折叠项应说明内容类型和规模，例如“查看 128 行命令输出”。

## 错误与恢复

错误信息必须依次说明：发生了什么、对任务的影响、用户下一步可采取的动作。

```text
无法读取目标文件
原因：文件不存在或当前工具没有访问权限。
影响：智能体无法继续生成基于该文件的修改。
操作：[重试] [更换文件] [查看详细日志]
```

- 不只展示错误码或堆栈。
- 可重试错误提供重试入口；需要选择时提供明确入口。
- 不自动重复高成本或具有外部影响的操作。

## 风险操作与确认

以下操作在执行前必须二次确认：删除本地文件、任务或历史记录；覆盖已有文件；批量应用变更；运行会修改系统或项目状态的命令；向外部服务发送内容或上传文件；导出含任务历史或本地文件内容的数据。

确认层必须说明操作内容、影响对象、是否可恢复，以及取消或返回路径。

## 空状态

首次使用或无任务时，主区不显示会话顶栏；展示简洁欢迎语和底部悬浮任务输入卡。欢迎语可引用当前工作目录或项目名称，位于主区视觉中心略偏下。个人工作流示例为可选内容，不应挤压留白或输入区域。不得展示团队邀请、账户配置、订阅或协作引导。
